# ADR-0004: передача файлов через проверяемую Git-ссылку

- Статус: принято
- Дата: 2026-07-26

## Контекст

Агенты на разных компьютерах часто работают с локальными копиями одного
репозитория. Передача содержимого файла через coordinator создаёт лишнюю копию
и требует отдельного хранения. Для committed-файла достаточно repository,
commit, относительного path и checksum.

Метаданные вложения приходят от другого агента и требуют локальной проверки.
Проверка должна сохранять рабочую ветку, index и файлы проекта получателя.

## Решение

`agent_start` и `agent_send` принимают до 20 вложений `git_file`:

```json
{
  "type": "git_file",
  "repository": "git@github.com:example/project.git",
  "revision": "a12bc34d",
  "path": "docs/plan.md",
  "sha256": "..."
}
```

Coordinator валидирует форму и сохраняет метаданные вместе с сообщением.
Worker выбранного проекта:

1. Принимает revision только в форме сокращённого или полного commit hash.
2. Принимает относительный Git path без `.` и `..`, обратных слешей и
   управляющих символов.
3. Находит корень локального репозитория.
4. Нормализует SSH- и HTTPS-адреса remote в одну repository identity.
5. Ищет commit локально и выполняет fetch совпавшего remote при его отсутствии.
6. Разрешает полный commit hash.
7. Читает blob через `git cat-file` и потоково вычисляет SHA-256.
8. Добавляет проверенный manifest в prompt Codex.

Git-команды запускаются без shell, имеют timeout и не получают device token в
окружении. Worker не выполняет checkout и не изменяет working tree.

## Последствия

- Git-вложение работает при наличии соответствующего remote у выбранного
  локального проекта.
- Доступ к private remote использует локальные Git credentials получателя.
- Ошибка repository, revision, path, fetch или checksum возвращается автору
  как failed result до запуска Codex turn.
- Временные и незафиксированные файлы передаются отдельным механизмом
  `temporary_file`.
