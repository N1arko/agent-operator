# ADR-0005: поиск и продолжение существующих задач Codex

- Статус: принято
- Дата: 2026-07-26

## Контекст

Задача Codex может существовать на локальном компьютере до подключения
Agent Operator и не иметь сопоставления с опубликованным проектом. Другому
агенту требуется найти такую задачу, увидеть её состояние и начать в ней новый
turn по точному `threadId`.

Полный обход rollout-файлов создаёт лишнюю дисковую нагрузку. Абсолютные пути
локального компьютера не должны попадать в coordinator.

## Решение

Добавлены две MCP-операции:

- `agent_threads` ставит worker запрос ограниченного поиска;
- `agent_thread_send` ставит новый turn в задачу по точному `threadId`.

`agent_threads` вызывает `thread/list` со следующими параметрами:

```json
{
  "limit": 10,
  "useStateDbOnly": true,
  "searchTerm": "optional title substring",
  "sortKey": "recency_at",
  "sortDirection": "desc",
  "archived": false
}
```

Лимит находится в диапазоне от 1 до 20. Worker возвращает ID, заголовок,
сокращённый preview, время обновления, status, source и сопоставленный
project descriptor. Поле `cwd` остаётся локальным. Поиск и результат проходят
через обычную mailbox-очередь и `agent_wait`.

`agent_thread_send` передаёт worker точный `threadId`. Worker:

1. Читает метаданные задачи через `thread/read` с `includeTurns: false`.
2. Возвращает `failed`, если задача выполняет активный turn.
3. Сопоставляет локальный `cwd` с опубликованным проектом, когда это возможно.
4. Вызывает `thread/resume` по ID без замены исходного `cwd`.
5. Запускает новый turn и сохраняет локальную привязку с nullable
   `projectId`.
6. Возвращает финальный ответ через `agent_wait`.

## Последствия

- Поиск использует индекс Codex state DB и не сканирует rollout-файлы.
- Размер ответа ограничен 20 краткими записями.
- Задачу вне project registry можно продолжить по известному ID.
- Активная задача сохраняет текущий turn; отправитель может повторить запрос
  после изменения status.
- `notLoaded` означает, что текущий app-server worker не наблюдает runtime
  задачи; поле availability для неё имеет значение `null`.
- app-server запускается по запросу и завершается по idle timeout.
