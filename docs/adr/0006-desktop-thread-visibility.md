# ADR-0006: обязательная видимость удалённой задачи в ChatGPT Desktop

- Статус: принято
- Дата: 2026-07-26

## Контекст

Фоновый `codex app-server` создаёт полноценную локальную задачу и выполняет
turn, однако приложение ChatGPT Desktop не переключается на неё автоматически.
Пользователь должен видеть запуск, ход работы и результат на принимающем
компьютере.

ChatGPT Desktop поддерживает canonical deep link
`codex://threads/<thread-id>`, открывающий локальную задачу по техническому ID.
App-server поддерживает `thread/name/set`.

## Решение

Worker версии `0.1.6` выполняет удалённый запуск в следующем порядке:

1. Создаёт или возобновляет thread через app-server.
2. Для нового thread задаёт заголовок `[Agent Operator] <краткий запрос>`.
3. Формирует deep link только из UUID, полученного от app-server.
4. Запускает Codex turn и получает `turnId`.
5. Передаёт `codex://threads/<thread-id>` операционной системе:
   - macOS — через `open`;
   - Windows — через `explorer.exe`.
6. Возвращает фактический `threadId` в result-сообщении.

Связанный steering повторно открывает активную задачу, чтобы входящее
уточнение было заметно пользователю.

## Последствия

- Каждый удалённый turn открывается в ChatGPT Desktop принимающего компьютера.
- Новые задачи имеют узнаваемый заголовок в sidebar и поиске.
- Отправитель получает точный ID созданной или продолженной задачи.
- Ошибка запуска deep link записывается worker, уже запущенный turn продолжает
  выполняться и возвращает результат.
- ChatGPT Desktop должен быть установлен, а пользовательская desktop-сессия
  должна быть активна.

Порядок `turn/start → deep link` выбран после реальной Windows-проверки:
открытие задачи перед `turn/start` создавало гонку между app-server worker и
ChatGPT Desktop. В sidebar появлялся thread с исходным вводом, выполнение turn
могло не начаться.

Официальный формат deep link:
<https://learn.chatgpt.com/docs/reference/commands#deep-links>.
