# ADR-0009: жизненный цикл временных файлов

- Статус: принято
- Дата: 2026-07-27

## Контекст

Агенты передают офисные документы и другие небольшие локальные файлы, которые
не входят в Git-репозиторий. Coordinator уже выполняет роль mailbox и доступен
обоим worker через исходящие HTTPS-соединения.

Для MVP требуется ограниченная по ресурсам доставка одного файла одному
получателю с проверяемой целостностью и автоматической очисткой.

## Решение

Coordinator предоставляет отдельный бинарный HTTP-контракт:

```text
POST /v1/files
GET  /v1/files/:fileId
POST /v1/files/:fileId/ack
```

Загрузка содержит identity получателя, имя файла и idempotency key в
заголовках. Coordinator вычисляет SHA-256, сохраняет содержимое в
`/data/files`, записывает метаданные в SQLite и возвращает attachment типа
`temporary_file`.

Attachment разрешается добавить в сообщение только владельцу загрузки и
только для выбранного при загрузке получателя. Повтор загрузки с тем же
idempotency key и тем же содержимым возвращает исходный `fileId`.

Получающий worker:

1. скачивает файл в каталог, привязанный к `messageId` и `fileId`;
2. проверяет срок действия, размер и SHA-256;
3. добавляет абсолютный локальный путь в prompt;
4. после публикации результата отправляет ack и удаляет локальную копию.

Coordinator удаляет файл после ack. Просроченные записи очищаются во время
файловых операций и на heartbeat с ограниченной частотой.

Начальные ограничения:

- 10 MiB на один файл;
- 50 MiB активных файлов одного отправителя;
- TTL 24 часа;
- до 20 вложений в одном сообщении.

## Последствия

Файл доступен владельцу и единственному получателю. Абсолютные пути
компьютеров между агентами не передаются: принимающий worker формирует свой
локальный путь после скачивания.

Coordinator буферизует одну загрузку в памяти в пределах 10 MiB. Этот объём
соответствует текущему MVP и лимиту контейнера. Хранилище S3 можно добавить
после появления подтверждённых объёмов, требующих потоковой загрузки или
внешнего object storage.

Файлы в Git продолжают передаваться через `git_file`; временное хранилище
обслуживает локальные файлы вне репозитория.
