# ADR-0007: устойчивое получение сообщений worker

- Статус: принято
- Дата: 2026-07-26

## Контекст

До версии `0.1.6` Windows-worker хранил cursor внутри каталога конкретной
версии. После обновления новый процесс начинал чтение с cursor `0`.
Coordinator возвращал всю историю адресованных сообщений вне зависимости от
их статуса. В результате три завершённых запроса `ready` были повторно
запущены и появились в ChatGPT Desktop как новые задачи.

Очередь worker находилась в памяти. Подтверждение доставки выполнялось до
локального сохранения, поэтому аварийный перезапуск мог привести к потере
принятого запроса.

## Решение

1. Worker хранит состояние в общем каталоге установки:
   `%LOCALAPPDATA%\AgentOperator\data\worker-state.json`.
2. Installer однократно переносит самое свежее состояние из каталога прежней
   версии, если общий файл ещё отсутствует.
3. Coordinator выдаёт worker только сообщения со статусом `queued`.
4. Worker сначала записывает запрос в `pendingMessages`, затем подтверждает
   доставку.
5. После перезапуска worker восстанавливает локальную очередь из
   `pendingMessages`.
6. Запрос удаляется из локальной очереди после успешной публикации result.
7. Повторная публикация result с тем же `replyTo` возвращает уже существующий
   результат.
8. Coordinator допускает максимум три незавершённых запроса для одного
   worker.

## Последствия

- Обновление worker не повторяет завершённую историю mailbox.
- Принятый запрос переживает перезапуск локального процесса.
- Ошибка сети при публикации result приводит к повторной доставке результата
  без создания второй записи.
- Максимальный backlog одного worker ограничен одной активной и двумя
  ожидающими операциями.
