# ADR-0001: интеграция worker с Codex app-server

- Статус: принято
- Дата: 2026-07-26

## Контекст

Worker должен запускать свежую задачу в выбранном локальном проекте, принимать
уточнение в связанную задачу, публиковать статус и восстанавливать работу после
перезапуска. Интеграция проверена с `codex-cli 0.146.0-alpha.3.1` и актуальной
экспериментальной схемой app-server.

## Решение

Worker управляет `codex app-server` по JSONL поверх STDIO:

- `thread/start` с локальным `cwd` создаёт свежую задачу;
- `turn/start` запускает работу;
- `turn/steer` доставляет уточнение в активный turn после события
  `item/started`;
- `thread/resume` по сохранённому `threadId` восстанавливает задачу после
  перезапуска app-server;
- `thread/status/changed`, `turn/started`, `item/started` и `turn/completed`
  служат источником состояния;
- итоговый текст извлекается из `agentMessage` завершённого turn. Актуальная
  обработка отдельных событий `item/completed` зафиксирована в ADR-0003.

Worker хранит соответствие `rootMessageId → threadId + projectId`. app-server
запускается лениво и завершается после периода бездействия.

## Проекты

В публичной схеме app-server отсутствует метод списка Codex-проектов и
стабильный project ID. Worker ведёт локальный реестр:

- стабильный случайный `projectId`;
- отображаемое имя;
- локальный абсолютный путь;
- необязательные теги.

Основная папка и дополнительные корни обнаруживаются локально при настройке
worker. Coordinator получает дескриптор без пути. Переименование или перенос
обрабатывается обновлением пути у прежнего `projectId`.

## Результаты проверки

Живой probe выполнил два раунда на macOS:

- запуск app-server: 34–47 мс;
- RSS сразу после запуска: около 52 МБ;
- RSS после активного turn: 174–196 МБ;
- `thread/start` с выбранным `cwd`: успешно;
- `turn/steer` в активный turn: принят за 1 мс;
- `turn/completed` и итоговый `agentMessage`: получены;
- полная остановка процесса и `thread/resume`: успешно;
- возобновление прежнего `threadId`: 40 мс;
- второй turn увидел историю и вернул `AOP001_RESUME_OK`.

CPU worker и app-server будет повторно измерен в вертикальном тесте. Probe
сохранён в `work/aop-001` как воспроизводимый локальный эксперимент и исключён
из Git.

## Последствия

Интеграция зависит от экспериментального API app-server. Worker проверяет
совместимость при старте и сообщает диагностическую ошибку при изменении
контракта. Локальный реестр проектов остаётся источником истины для выбора
проекта.
