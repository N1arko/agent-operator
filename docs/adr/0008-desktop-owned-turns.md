# ADR-0008: видимый turn должен принадлежать ChatGPT Desktop

- Статус: подтверждено; Windows-реализация принята в ADR-0010
- Дата: 2026-07-26

## Контекст

ChatGPT Desktop запускает собственный `codex app-server` через stdio. Worker
Agent Operator запускает второй процесс app-server. Оба процесса могут знать
один `threadId`, однако открытое приложение не получает события turn,
выполненного worker.

Официальный deep link `codex://threads/<thread-id>` открывает локальную задачу.
Документация не заявляет синхронизацию активной истории или автоматическую
отправку prompt. Публичный app-server transport поддерживает отдельные клиенты,
а Desktop не публикует endpoint своего stdio-процесса.

## Требование

Turn, который пользователь должен наблюдать в ChatGPT Desktop, запускается
через runtime самого приложения. Backend-result от отдельного app-server
сохраняется как headless-режим и не считается подтверждением Desktop E2E.

## Следующий эксперимент

Полный перезапуск Desktop после внешнего turn подтвердил общую сохранённую
историю: prompt и result появились в исходной задаче. Ограничение находится в
активном Desktop app-server, который не перечитывает внешние изменения.

Windows Desktop follower IPC подтвердил возможность открыть точную задачу и
запустить turn через локальный host приложения. Реализация и живой E2E
зафиксированы в ADR-0010. Prompt, статус выполнения и ответ появляются в
открытой задаче без ручного обновления пользователем.

Создание новой проектной задачи и проверка macOS вынесены в AOP-076.
