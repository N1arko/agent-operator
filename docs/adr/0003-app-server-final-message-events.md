# ADR-0003: финальный текст из событий app-server

- Статус: принято
- Дата: 2026-07-26

## Контекст

Удалённый Windows-тест с npm Codex `0.145.0` успешно создал и завершил свежий
thread. Событие `turn/completed` содержало статус `completed` и пустой массив
items. Итоговое `agentMessage` было передано отдельным событием
`item/completed`. Worker `0.1.1` читал только items завершённого turn и вернул
пустой текст.

Актуальная схема app-server описывает `item/completed` как источник
завершённого `ThreadItem`, а `turn/completed` как сигнал окончания turn.
Поле `phase` у `agentMessage` различает `commentary` и `final_answer`, при этом
может отсутствовать у совместимых провайдеров.

## Решение

Worker `0.1.2`:

- сохраняет поток событий app-server до завершения turn;
- собирает `agentMessage` из `item/completed` для конкретных `threadId` и
  `turnId`;
- дополняет их items из `turn/completed` для совместимости с прежними версиями;
- устраняет дубли по item ID;
- выбирает сообщения с `phase = "final_answer"`;
- использует сообщения без phase как совместимый fallback;
- удаляет `AOP_DEVICE_TOKEN` из окружения дочернего app-server.

Парсер покрыт отдельными тестами для обеих форм событий, выбора финального
сообщения и изоляции соседних turns.

## Последствия

Статус turn и его итоговый текст обрабатываются как два связанных потока
данных. Кольцевой буфер worker должен сохранять завершающее `item/completed` до
следующего `turn/completed`. Device token остаётся доступен worker и не
передаётся процессу Codex через environment.
