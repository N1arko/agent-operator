# Миграция private coordinator 0.1.23 на generic self-hosted profile

Миграция выполняется после сборки и проверки нового image на отдельном data
directory. Текущий deployment продолжает обслуживать worker до согласованного
окна переключения.

## Подготовка

1. Зафиксировать exact текущий image/source revision и сохранить SQLite
   snapshot средствами 0.1.23.
2. Скопировать snapshot в изолированный staging data directory.
3. Сохранить текущую legacy token map только в локальном operator vault.
4. Настроить `deploy/self-hosted/.env` с тем же публичным URL и allowed host.
5. Запустить generic image на отдельном loopback port и проверить `/health`.

При первом старте создаётся `credential.key`, а schema получает enrollment и
device tables. Legacy `AOP_DEVICE_TOKENS` можно временно передать container для
непрерывной работы существующих worker. Новые devices подключаются через
`aopctl device create`.

## Переключение

1. Остановить запись в старый coordinator и создать финальный snapshot.
2. Запустить generic coordinator с финальной базой и сохранённым
   `credential.key` staging-проверки либо с новым key до первого enrollment.
3. Проверить doctor, health, legacy heartbeat, MCP и один вертикальный request.
4. Переключить edge route на новый container.
5. По одному заменить legacy worker token через enrollment и проверить revoke.
6. Удалить `AOP_DEVICE_TOKENS` после миграции всех identities.

## Rollback

Edge route возвращается на immutable 0.1.23 image. Для rollback используется
pre-migration SQLite snapshot; новая база с дополнительными tables сохраняется
отдельно для диагностики. Worker с уже заменённым credential получает прежний
legacy token из operator vault до повторного переключения.

Production rollout выполняется отдельным наблюдаемым действием после local и
clean-room acceptance. Эта инструкция не меняет работающий private deployment.
