# Инструкции для Codex

## Старт каждой сессии

Первым действием прочитать `specs/protocols/BOOT.md` и выполнить его
последовательно. Локальная идентичность исполнителя хранится в `specs/.me`.

## Цель проекта

Разработать Agent Operator — безопасный координатор сообщений и задач между
независимыми Codex-агентами на разных аккаунтах и компьютерах.

## Источники истины

Приоритет источников: инструкция пользователя → активные `specs/` → тесты →
код.

- `specs/common/` — общесистемный канон.
- `specs/modules/` — продуктовые, модульные и инфраструктурные спецификации.
- `specs/BOARD.md` — зарегистрированная работа.
- `specs/WAL.md` — handoff только активной работы.
- `specs/TECHDEBT.md` — осознанные технические компромиссы.
- `docs/adr/` — история существенных архитектурных решений.
- `docs/` — эксплуатационные инструкции, E2E-доказательства и исторический
  контекст.
- `KANBAN.md` — исторический журнал карточек до перехода на spec-driven
  workflow.

## Режим ведения проекта

Codex является основным исполнителем проекта и самостоятельно выполняет
исследование, проектирование, программирование, тестирование, документацию и
подготовку развёртывания. Участие пользователя требуется для предоставления
credentials, доступа к инфраструктуре, выбора бизнес-приоритетов и подтверждения
необратимых внешних действий.

Каждая новая рабочая сессия продолжает относящийся к ней work item из
`specs/BOARD.md`. Если активной работы нет, Codex создаёт или уточняет
управляющую спеку до изменения spec-owned кода.

## Правила работы

1. Перед изменениями выполнить `specs/protocols/BOOT.md`.
2. В `BOARD.md` держать одну основную инженерную карточку в `In Progress`.
3. Для активной карточки, переходящей между сессиями, вести секцию в `WAL.md`.
4. После завершения переместить карточку в `Done`, удалить активную секцию WAL
   и обновить управляющую спеку.
5. Новый или существенно изменённый spec-owned код размечать полным
   `@spec spec://...#anchor` на точках ответственности.
6. Существенные технические решения фиксировать ADR и связывать с управляющей
   спекой.
7. Пользовательскую документацию вести на русском, код и технические
   идентификаторы — на английском.
8. Сохранять минималистичную модель данных: VPS работает как mailbox и
   presence-сервис для агентов.
9. OpenAI credentials и токены внешних сервисов сохранять на соответствующем
   host. Coordinator работает со своими device credentials.
10. Worker использует исходящее соединение к coordinator.
11. `agents_list` показывает зарегистрированных исполнителей, `agent_projects`
   показывает их локальные Codex-проекты. Список чатов через эти инструменты не
   публикуется.
12. `agent_start` создаёт свежий thread в явно выбранном проекте. Занятый агент
    сохраняет такой запуск в очереди.
13. `agent_send` с `replyTo` продолжает связанную сессию. Один агент выполняет
    один активный turn.
14. Worker автоматически выводит статус из событий app-server и отправляет
    итоговый ответ после `turn/completed`.
15. `codex app-server` запускается по запросу и останавливается после idle
    timeout. Worker остаётся постоянно доступным.
16. Файлы из репозиториев передавать ссылкой на commit, относительный путь и
    checksum. Локальные файлы передавать временным вложением с TTL.
17. Coordinator разворачивается контейнером на SSH-host `clawvpn`. Существующие
    сервисы сервера сохраняются без изменений.
18. Каждое сетевое изменение проектировать с idempotency, timeout, retry и audit.
19. Для новой функциональности добавлять тесты соответствующего уровня.
20. Перед завершением задачи запускать typecheck, lint и доступные тесты.
21. Инфраструктурные компоненты добавлять после появления подтверждённой
    потребности в текущем вертикальном сценарии.
22. При достижении `CP-WIN-01` проверить входные критерии, сформировать
    актуальную задачу для Windows Codex по шаблону из
    `docs/CHECKPOINT_WINDOWS.md` и остановиться для подключения пользователя.
23. `CP-WIN-01` завершается только после наблюдаемого heartbeat Windows-worker,
    выдачи проектов и успешного тестового `agent_start`.

## Стиль публичных текстов

Избегать формулировок-противопоставлений. Писать прямо, спокойно и предметно.
