# Инструкции для Codex

## Цель проекта

Разработать Agent Operator — безопасный координатор сообщений и задач между
независимыми Codex-агентами на разных аккаунтах и компьютерах.

## Источники истины

- `docs/PROJECT_BRIEF.md` — продуктовая концепция и границы.
- `docs/ARCHITECTURE.md` — текущая архитектура.
- `docs/CHECKPOINT_WINDOWS.md` — обязательный checkpoint реального
  Windows-worker.
- `KANBAN.md` — порядок и статус работ.
- Архитектурные решения после начала реализации хранятся в `docs/adr/`.

## Режим ведения проекта

Codex является основным исполнителем проекта и самостоятельно выполняет
исследование, проектирование, программирование, тестирование, документацию и
подготовку развёртывания. Участие пользователя требуется для предоставления
credentials, доступа к инфраструктуре, выбора бизнес-приоритетов и подтверждения
необратимых внешних действий.

Каждая новая рабочая сессия продолжает текущую карточку `KANBAN.md`. После её
завершения Codex выбирает следующую карточку с учётом зависимостей и цели MVP.

## Правила работы

1. Перед изменениями прочитать относящиеся к задаче документы и карточку канбана.
2. В колонке «В работе» держать одну основную инженерную карточку.
3. После завершения переместить карточку в «Готово» с датой и результатом.
4. Существенные технические решения фиксировать ADR.
5. Пользовательскую документацию вести на русском, код и технические
   идентификаторы — на английском.
6. Сохранять минималистичную модель данных: VPS работает как mailbox и
   presence-сервис для агентов.
7. OpenAI credentials и токены внешних сервисов сохранять на соответствующем
   host. Coordinator работает со своими device credentials.
8. Worker использует исходящее соединение к coordinator.
9. `agents_list` показывает зарегистрированных исполнителей, `agent_projects`
   показывает их локальные Codex-проекты. Список чатов через эти инструменты не
   публикуется.
10. `agent_start` создаёт свежий thread в явно выбранном проекте. Занятый агент
    сохраняет такой запуск в очереди.
11. `agent_send` с `replyTo` продолжает связанную сессию. Один агент выполняет
    один активный turn.
12. Worker автоматически выводит статус из событий app-server и отправляет
    итоговый ответ после `turn/completed`.
13. `codex app-server` запускается по запросу и останавливается после idle
    timeout. Worker остаётся постоянно доступным.
14. Файлы из репозиториев передавать ссылкой на commit, относительный путь и
    checksum. Локальные файлы передавать временным вложением с TTL.
15. Coordinator разворачивается контейнером на SSH-host `clawvpn`. Существующие
    сервисы сервера сохраняются без изменений.
16. Каждое сетевое изменение проектировать с idempotency, timeout, retry и audit.
17. Для новой функциональности добавлять тесты соответствующего уровня.
18. Перед завершением задачи запускать typecheck, lint и доступные тесты.
19. Инфраструктурные компоненты добавлять после появления подтверждённой
    потребности в текущем вертикальном сценарии.
20. При достижении `CP-WIN-01` проверить входные критерии, сформировать
    актуальную задачу для Windows Codex по шаблону из
    `docs/CHECKPOINT_WINDOWS.md` и остановиться для подключения пользователя.
21. `CP-WIN-01` завершается только после наблюдаемого heartbeat Windows-worker,
    выдачи проектов и успешного тестового `agent_start`.
