# PROP-003: Пользовательская поверхность {#root}

## Простыми словами {#plain-language}

Agent Operator использует обычный чат Codex и существующий Codex Desktop.
Собственного графического интерфейса в текущей версии нет.

## 1. Назначение {#goal}

Зафиксировать, что пользователь должен видеть при удалённой работе, и какие
состояния считаются достоверными.

## 2. Поверхности {#surfaces}

- Обычный чат отправителя вызывает MCP через routing skill.
- Новая удалённая задача появляется в проекте Desktop получателя с заголовком
  `[Agent Operator] …`.
- Существующая задача получает новый user turn.
- Открытая карточка показывает prompt, прогресс и финальный ответ без
  перезапуска Desktop.
- Отправитель получает осмысленные update с `isFinal: false` и один итоговый
  result с `isFinal: true`.

## 3. Состояния {#states}

- `idle`: worker доступен, активного turn нет.
- `busy`: worker выполняет один turn.
- `offline`: heartbeat устарел.
- `error`: worker сообщает неисправность.
- `queued`: запрос принят и ждёт исполнения.
- `cancelled`, `failed`, `completed`: терминальный результат отражает
  фактическое завершение.

Пустая карточка после завершённого удалённого turn считается дефектом
Desktop delivery. Промежуточный read-only статус не меняет терминальное
состояние, пока Desktop продолжает работу.

## 4. Язык и обратная связь {#language}

Названия инструментов и ID остаются техническими. Пользовательские сообщения
кратко объясняют состояние, следующий шаг и причину ошибки. Опасное действие
отмены требует точный request ID.
