# PROP-004: Продуктовая модель и сценарии {#root}

## Простыми словами {#plain-language}

Пользователь просит один Codex обратиться к другому компьютеру. Отправляющий
агент выбирает исполнителя и способ доставки, принимающий worker выполняет
работу в локальном контексте и возвращает результат.

## 1. Термины {#terms}

| Термин | Значение |
| --- | --- |
| agent | зарегистрированный локальный worker с именем и состоянием |
| caller | Codex, создающий MCP-запрос |
| recipient | агент, которому адресована работа |
| project | локально настроенный каталог с устойчивым публичным ID |
| task/thread | локальная задача Codex |
| turn | одно выполнение модели внутри задачи |
| root request | первое сообщение цепочки Agent Operator |
| result | единственный автоматический итог исполнения запроса |

## 2. Участники {#roles}

### Пользователь {#roles.user}

Выбирает намерение, целевой компьютер или проект, приоритеты развития и
подтверждает действия с внешними последствиями.

### Отправляющий Codex {#roles.caller}

Получает актуальный список агентов, выбирает подходящий инструмент, передаёт
контекст, ждёт результат и продолжает основную работу.

### Принимающий worker и Codex {#roles.recipient}

Разрешают локальный контекст, исполняют один активный turn, показывают его в
Desktop и возвращают итог.

## 4. Общие правила {#rules}

- Один worker выполняет один активный turn.
- Новая работа не сбивает текущую и ждёт в ограниченной очереди.
- Follow-up привязывается через `replyTo` или точный `threadId`.
- Итог публикуется автоматически один раз.
- Model и reasoning effort являются опциональными и проверяются на recipient.
- Агенты могут выполнять независимые задачи параллельно на разных host.
