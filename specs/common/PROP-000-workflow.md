# PROP-000: Workflow и качество {#root}

## Простыми словами {#plain-language}

Человек задаёт намерение, спека хранит канон, тесты проверяют его, код
реализует. Доска показывает зарегистрированную работу, WAL помогает передать
активную сессию.

## 1. Назначение {#goal}

- Установить единый порядок работы.
- Сделать связь требований, реализации и проверок наблюдаемой.
- Сохранить достаточный контекст между агентами и сессиями.

## 2. Правила workflow {#workflow}

- Каждая сессия начинается с `specs/protocols/BOOT.md`.
- Новая возможность получает FEAT или INFRA до изменения spec-owned кода.
- Изменение существующего поведения обновляет его текущую управляющую спеку.
- Одна основная инженерная карточка находится в `BOARD#In Progress`.
- WAL создаётся только для активной работы с handoff.
- Существенное решение получает ADR; компромисс получает TECHDEBT.
- Пользовательские документы ведутся на русском, технические идентификаторы и
  код — на английском.

## 3. Трассировка {#traceability}

Новый и существенно изменённый spec-owned код получает полный `@spec` на
обработчике, сервисе, runtime-процессе, конфигурации или тесте, где находится
ответственность. Маркер указывает актуальное правило, сценарий или контракт.

Существующий код версии 0.1.18 размечается по мере содержательных изменений.
Массовое добавление комментариев без изменения ответственности не требуется.

## 4. Качество {#quality}

Для каждого work item определяются:

- автоматические тесты и ручные E2E;
- ожидаемые точки `@spec`;
- риск регрессии и путь отката;
- обновляемые пользовательские и эксплуатационные документы.

Перед завершением выполняются `pnpm typecheck`, `pnpm lint` и `pnpm test`.
Документальная работа дополнительно проверяет уникальность номеров,
существование `spec://`-файлов и якорей.

## 5. Definition of Done {#done}

- Критерии управляющей спеки выполнены.
- Тесты и проверки прошли.
- Канон и changelog обновлены.
- BOARD переведён в Done.
- Активная секция WAL удалена.
- Открытые REVIEW и TECHDEBT перечислены в отчёте.
