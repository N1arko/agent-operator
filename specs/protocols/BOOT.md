# BOOT: старт рабочей сессии

Выполнять перед изменением проекта.

## 1. Идентичность

Прочитать `specs/.me`. Если файла нет, создать его из `.me.template` с
уникальным локальным handle до регистрации активной работы.

## 2. Контекст

1. Прочитать корневой `AGENTS.md`.
2. Прочитать `specs/common/main.md` и `specs/common/structure.md`.
3. Найти управляющую `PROP`, `FEAT` или `INFRA`.
4. Прочитать только относящиеся к задаче строки `BOARD.md`, `WAL.md` и
   `TECHDEBT.md`.
5. Для новой или существенно перерабатываемой спеки применить
   `SPEC-AUTHORING-PROTOCOL.md`.

## 3. Регистрация работы

- Мелкая одношаговая правка, полностью завершаемая в текущей сессии, может
  выполняться без BOARD и WAL.
- Отслеживаемая работа должна иметь спеку и строку в BOARD.
- При переходе в `In Progress` назначить owner из `.me`.
- Если работа потребует handoff, создать секцию в WAL с тем же owner.
- В `In Progress` держать одну основную инженерную карточку.

## 4. Выполнение

- Приоритет: инструкция пользователя → спека → тесты → код.
- Обновить спеку до кода, если меняется каноническое поведение.
- Новый и существенно изменённый spec-owned код разметить полным `@spec`.
- Добавить проверки, соответствующие риску изменения.
- Осознанный компромисс записать в TECHDEBT.
- Существенное техническое решение записать в ADR.

## 5. Завершение

1. Запустить typecheck, lint и доступные тесты.
2. Сверить критерии готовности управляющей спеки.
3. Обновить её changelog.
4. Переместить work item в `Done`.
5. Удалить активную секцию WAL.
6. В отчёте указать результат, проверки, открытые вопросы и оставшийся долг.
